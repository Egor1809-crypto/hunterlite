# Оценка качества консультации

Новые текстовые и голосовые тренировки используют `conversation-quality-v1`.
Сервер начисляет баллы за 20 действий: полное выполнение — весь вес, частичное —
половина, отсутствие доказательства — ноль. Количество реплик, длина разговора,
настроение клиента и факт продажи не добавляют баллов.

| Критерий | Максимум |
| --- | ---: |
| Выяснение ситуации | 18 |
| Работа с сомнениями | 12 |
| Ясность и уважение | 12 |
| Рекомендация и следующий шаг | 18 |
| Глубина разбора | 5 |
| Поддержка клиента | 10 |
| Правовая точность | 25 |

Штрафы: грубость −10; давление, необоснованная гарантия или подтверждённая
правовая ошибка −15 за категорию; тяжёлое оскорбление/угроза или незаконный
совет −25. Повторы одной категории не умножают штраф. Тяжёлое оскорбление
заменяет штраф за грубость и ограничивает итог 20; незаконный совет — 10.
Итог = сумма начислений и штрафов, ограниченная диапазоном 0–100 и критическим
ограничением. Отсутствие нарушения само по себе баллов не даёт.

Каждое начисление и нарушение содержит точную цитату из реплики юриста.
Правовая оценка дополнительно требует цитаты из актуального чанка базы знаний.
Сервер проверяет индексы, роли, цитаты, идентификаторы критериев и источников,
а затем самостоятельно считает итог. Непроверенные юридические утверждения,
неполный ответ модели или ошибка провайдера оставляют оценку недоступной.
Сбой анализа не считается нулевым качеством консультации.

Модель задаётся `CONVERSATION_SCORING_MODEL`, провайдер — существующий NAVY_LLM.
Для оценки используется отдельный запрос JSON без ролевых инструкций клиента,
подмены контента рассуждениями модели и вымышленных резервных итогов.
Текст и голос используют один оценщик. Старый алгоритм сохранён только для
сравнения исторических отчётов (`calculate_legacy_scores`); новые результаты
через него не рассчитываются. Числовая оценка во время разговора не показывается.

Пересчёт старых результатов запускает сам пользователь. Эндпоинт
`POST /training/sessions/{id}/rescore-call` сохраняет прежнюю оценку в
`_previous_assessment`, проверяет владельца и блокирует строку на время пересчёта.
Параллельные запросы получают один результат. Завершение сессии, покупки и XP
повторно не выполняются. Массового изменения истории нет.

Для проверки рабочего провайдера: `python -m scripts.evaluate_conversation_quality`
из `apps/api`. Команда читает тестовые диалоги и актуальные правовые источники,
проверяет допустимые диапазоны оценок и категории нарушений. Сессии и реальные
пользовательские результаты не меняются. Обращения к провайдеру оплачиваются
обычным образом; в CI запускаются только автономные тесты без вызова ИИ.
